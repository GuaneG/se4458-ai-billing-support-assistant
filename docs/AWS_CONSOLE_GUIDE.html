1. Mimari ve başlangıç değerleri

Tarayıcı Gateway'in HTTPS URL'sini açar. Gateway, VPC Link V2 üzerinden aynı EC2'deki Chat ve Billing servislerine gider. AWS Cloud Map iki hedefin private IP ve portunu bildirir. Domain, NAT Gateway ve load balancer bu tasarım için gerekmez. EC2'nin public IPv4 adresi outbound internet ve kısıtlı SSH içindir. Chat, OpenAI'ya HTTPS, MCP'ye loopback üzerinden Streamable HTTP ile ulaşır. Billing REST tool çağrıları Gateway HTTPS URL'sine gider. Böylece Chat'in dışarıdan çağrılan endpoint'leri ve Agent'ın içinden yapılan Billing REST çağrıları aynı Gateway üzerinden izlenebilir.

4. Gateway ve private integration

  1. Cloud Map'te se4458 adlı HTTP namespace oluştur. Instance discovery alanında API calls seç. İki service oluştur (billing ve chat). Her birinde Register service instance → IP address seçip EC2 private IPv4 ve sırasıyla 8000 / 8002 gir. DNS veya health check bu tek instance demo için gerekli değil. EC2 instance kayıt türü yerine IP address alanı portu da kaydeder. Register işleminin tamamlandığını kontrol et.
  2. API Gateway'de se4458-link adlı VPC Link V2 oluştur. EC2 ile aynı VPC'nin desteklenen AZ'lerindeki subnet'leri ve billing-link SG'yi seç. Link AVAILABLE olana kadar bekle. VPC Link'in subnet ve SG seçimi sonradan değişmez.
  3. API Gateway'de HTTP API oluştur. $default stage ve Auto-deploy kullan. Bu sayede canlı URL'ye stage prefix eklenmez ve Chat'in /chat-assets ile /api/v1 istekleri aynı origin'de çalışır.
  4. İki private resource integration oluştur. Türü HTTP proxy, hedefi ilgili Cloud Map service ARN, VPC Link'i se4458-link, integration method'u ANY, payload format version 1.0. Her integration'da path mapping'i overwrite:path = $request.path ile ayarla. Console'da Manage integrations altında hedef integration için Parameter mapping alanını kullan. Varsayılan HTTP API timeout değeri 30 saniyeyi aşamaz.
  5. Aşağıdaki route'ları ilgili integration'a bağla. App'in HS256 token'ı için Gateway route authorization NONE kalır. Uygulamalar gelen Authorization: Bearer ... header'ını doğrular. API Gateway'in hazır JWT authorizer'ı RSA tabanlı token bekler. Bu projede korumayı FastAPI uygular. Tarayıcı ve API aynı URL'yi kullandığından CORS ayarı gerekmiyor.
  6. Stage Logging ayarına kısa saklama süreli bir CloudWatch log group ekleyebilirsin. Access log için örnek format aşağıda. Authorization header, body, token veya parola kaydetme. Stage Throttling bölümünde demo trafiğine uygun bir limit seçebilirsin. Login için örnek başlangıç 2 requests/s, burst 5. Bu yaklaşık ve paylaşılan bir route limitidir.
  7. Stage'deki Invoke URL'yi kopyala. EC2 üzerindeki ~/.config/se4458/chat.env içinde BILLING_API_BASE_URL değerini bu HTTPS URL ile değiştir ve sudo systemctl restart se4458@chat çalıştır.
{"requestId":"$context.requestId","routeKey":"$context.routeKey","status":"$context.status","integrationStatus":"$context.integration.status","integrationLatency":"$context.integration.latency"}

5. Canlı kabul ve teslim kanıtları

İlk iki Gateway route'u ve auth

Tarayıcıda Invoke URL'yi aç. Login ekranı, CSS ve JS yüklenmeli. Windows PowerShell'de Invoke URL'yi gerçek HTTPS değerine çevirip aşağıdaki bloğu çalıştır. curl.exe status kodunu gösterir ve login token'ı process belleğinde tutulur.

$gw = 'https://YOUR_API_ID.execute-api.YOUR_REGION.amazonaws.com'
$billPath = '/api/v1/subscribers/A001/bills/2026/10'
$detailsUrl = "$gw$billPath/details?page=2&pageSize=1"
curl.exe -sS -o NUL -w "summary HTTP %{http_code}\n" "$gw$billPath"
curl.exe -sS -o NUL -w "no JWT HTTP %{http_code}\n" $detailsUrl

$demoSecret = Read-Host 'A001 demo password' -AsSecureString
$credential = [pscredential]::new('A001', $demoSecret)
$loginBody = @{username = 'A001'; password = $credential.GetNetworkCredential().Password} | ConvertTo-Json -Compress
try {
    $session = Invoke-RestMethod -Method Post -Uri "$gw/api/v1/auth/login" -ContentType 'application/json' -Body $loginBody -ErrorAction Stop
    $auth = @{Authorization = "Bearer $($session.token)"}
    $details = Invoke-WebRequest -UseBasicParsing -Uri $detailsUrl -Headers $auth -ErrorAction Stop
    "owner JWT HTTP $($details.StatusCode)"
    $details.Content | ConvertFrom-Json | Select-Object total, remainingBalance, page, pageSize, totalItems
} finally {
    Remove-Variable loginBody, credential, demoSecret, session, auth -ErrorAction SilentlyContinue
}
