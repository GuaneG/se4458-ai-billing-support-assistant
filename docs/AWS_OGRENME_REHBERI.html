Gateway’den önce hangi endpoint’ler vardı?

Chat ve Billing zaten FastAPI uygulamalarıydı. İlk yerel demoda agent/chat_demo.py bileşenleri tek Python sürecinde bir araya getiriyordu. EC2’de bunları ayrı servisler olarak ayağa kaldırıp Billing’i önce host içinden curl ile test ettik. Gateway route’u, gelen HTTP method + path ikilisine bir hedef bağlar. Integration da o hedefe hangi VPC Link ve Cloud Map kaydı üzerinden gidileceğini söyler.

FastAPI’nin geliştirme dokümanları ve OpenAPI endpoint’leri de uygulama düzeyinde bulunur. Gateway’e eklediğimiz route’lar yukarıdaki tablolardadır. MCP araması ayrı bir HTTP taşıması kullanır ve EC2’ye içeriden 127.0.0.1:8001/mcp üzerinden ulaşır.

Trafiği kim kontrol eder?

Bir istek ağ bağlantısı kurabilir ve uygulama yetkisi olmadığı için yine de reddedilebilir. Aşağıdan bir örnek seçip hangi katmanın karar verdiğini gör.

  • Public API Gateway
    HTTPS girişini karşılar ve method/path eşleştirir. $default stage, URL’yi kökten açar. $default adlı bir catch-all route ayrı bir ayardır. Bu kurulumda korumalı endpoint’lerin JWT kontrolünü FastAPI yapar. Stage throttling ve access logs ayrı ayarlardır. Konuşmada bunların canlı durumu doğrulanmadı.
  • billing-link
    VPC Link’in ENI’lerine bağlı. Yeni outbound TCP bağlantısı için hedef launch-wizard-2 grubuna bağlı olmalı ve hedef port 8000 veya 8002 olmalı. Yeni inbound bağlantı kuralı yok. Tarayıcıdan Gateway’e yapılan public HTTPS çağrısı bu ENI’de başlamaz. Bu grup, Gateway’in EC2’ye açtığı bağlantıyı kontrol eder.
  • launch-wizard-2
    EC2’ye bağlı. Inbound TCP 8000/8002 için kaynak billing-link, SSH 22 için kendi public IPv4 /32 kuralı var. Konuştuğumuz yapıdaki outbound All traffic, EC2’den public HTTPS bağlantılarına izin verir.
  • Loopback
    MCP 127.0.0.1:8001, PostgreSQL host portu 127.0.0.1:55458. Bu trafik EC2 içinde kalır. Gateway’de bu servislere ayrılmış route bulunmaz.

Ayrı Security Group ne kazandırdı?

Bir VPC Link için kullanılacak grubun adı serbest. Bu grup, yalnız gerekli hedef ve portlara izin vermeyi ve EC2 inbound kuralında VPC Link’i kaynak olarak tanımayı kolaylaştırır. Mevcut billing-link kuralı kaldırılır ve başka bir izin tanımlanmazsa Gateway’in private bağlantısı kurulamaz.

Cevap için neden ayrıca port açmadık?

Security Group stateful. Örneğin EC2 geçici bir kaynak portundan OpenAI’nin 443 portuna bağlanınca cevap o kurulu bağlantının parçasıdır ve geri geçer. Aynı mantıkla Billing cevabı VPC Link’e döner. İki durumda da yeni bir inbound bağlantı başlatılmaz.

Chat, Agent ve tool nesneleri

agent/web/ tarayıcıdaki arayüz. agent/chat_api.py login, JWT ve Chat HTTP handler’larını çalıştırır. agent/billing_agent.py modele tool şemalarını sunar, modelin function_call çıktısını çalıştırır ve aynı call_id ile function_call_output gönderir. agent/billing_client.py REST isteklerinin path’ini ve yetki header’ını oluşturur. agent/operator_api.py operatör onay akışını yürütür.

Billing, PostgreSQL ve işlemler

billing_api/routers/bills.py versioned REST route’larını tanımlar. billing_api/db/bills.py aylık kullanım, hesaplanmış fatura ve ödeme kayıtlarını okur/yazar. billing_api/services/pricing.py blok fiyatlandırmasını hesaplar. Operatör hesabı PostgreSQL’e hash ile yazılır. Docker named volume veriyi tutar.

MCP ve rehber araması

mcp_server/server.py, search_billing_documentation tool’unu ve Streamable HTTP endpoint’ini açar. Rehber indeksi başlık ve bölüm metinlerini eşleştirir. Model, tool’un query değerini üretir. SDK oturumu başlatırken HTTP mesajı gönderebilir. tools/call yalnız arama tool’u seçilince gider.

Uygulama kodu ve AWS konfigürasyon dosyaları

/etc/systemd/system/se4458@.service ortak şablon. se4458@chat için %i değeri chat olur ve /home/ubuntu/.config/se4458/chat.env yüklenir. Billing ve MCP kendi dosyalarını okur. Tek Chat worker onay taslaklarını bellekte tutar. Restart sonrasında bekleyen taslak yeniden hazırlanır.

API key ve JWT hangi istekte kullanılıyor?

OpenAI API key

Chat servisi chat.env üzerinden OPENAI_API_KEY değerini okur. OpenAI SDK bu değeri api.openai.com/v1 tarafına yaptığı HTTPS çağrısında kullanır. Model proje kodunda gpt-6-luna. Harcama OpenAI projesine yazılır. Key, tarayıcıya sunulan JS dosyasına dahil edilmez.

Uygulama JWT’si

Login başarılı olunca Chat, abone kimliği veya operatör yetkisi için kendi JWT’sini üretir. Tarayıcı bunu Authorization: Bearer … olarak Chat’e yollar. Agent, korumalı Billing isteğine aynı oturumun token’ını koyar. Chat ve Billing, ortak BILLING_JWT_SECRET ile token’ı doğrular.

  • BILLING_API_BASE_URL
    Chat’in Billing isteklerinin başladığı adres. Kodda bu değer verilmezse http://127.0.0.1:8000 fallback’i var. EC2’de değeri Gateway Invoke URL’sine çevirdik ve se4458@chat servisini restart ettik. Böylece Agent’ın query_bill, query_bill_details ve ilgili yazma istekleri Gateway’den geçiyor.
  • MCP_URL
    Chat’in MCP’ye ulaşacağı yerel adres. Model MCP tool’unu seçince Agent 127.0.0.1:8001/mcp üzerinden çağırır.
  • BILLING_DATABASE_URL
    PostgreSQL bağlantı ayarı. Billing işlem kayıtlarını buradan okur/yazar. Chat de operatör hesabı gibi kendi veritabanı erişimlerinde kullanır.

Bir Chat isteğinin içindeki model çağrıları aynı tool sonuçlarını birlikte taşır. Yeni bir Chat mesajında Agent yeni bir history listesi açar. Bu yüzden “Emin misin?” gibi bir soru tek başına önceki faturayı bulamayabilir.

Bugün neyi neden yaptık?

  1. EC2, SSH ve disk

    Stockholm’de Ubuntu 26.04 ARM64 t4g.small başlattık. SSH kaynağını kendi IP’mize daralttık ve Windows anahtar izinlerini düzelttik. 16 GiB şifreli gp3 EBS, uygulama dosyaları ve Docker verisi için disk sağladı. Uygulama sunucusu olmadan Chat ve Billing’in çalışacağı hedef olmazdı.

  2. Kaynak arşivi, Python ve Docker

    scp kaynak arşivini EC2’ye taşıdı; tar proje klasörüne açtı. Python bağımlılıklarını .venv ile ayırdık. Docker Compose, PostgreSQL’i ve kalıcı volume’ünü oluşturdu. psql ile demo Ekim faturasını gördük.

  3. Servis ayarları ve systemd

    DB, JWT, demo parola ve OpenAI key ayarları EC2’de ilgili environment dosyalarına girdi. Gizli değerleri 600 izinli yapılandırma dosyalarından okuyoruz. Ortak systemd şablonu üç Python uygulamasını ayrı portlarda ayakta tutar; SSH oturumu kapansa da çalışırlar.

  4. Cloud Map ve Security Groups

    Cloud Map’te se4458 HTTP namespace’ine chat ve billing için aynı private IP’yi iki farklı portla kaydettik. Cloud Map hedefi bildirir. billing-link ve launch-wizard-2 kuralları bağlantının VPC’de gerçekten kurulmasına izin verir.

  5. VPC Link ve subnet seçimi

    API Gateway’in VPC içinde ağ arayüzü açabilmesi için se4458-link oluşturduk. İki subnet seçimi link arayüzlerini farklı AZ’lere yayar. Uygulamanın tek EC2’si eu-north-1c’de. İkinci subnet, EC2’nin ikinci bir kopyasını oluşturmaz.

  6. HTTP API, stage, integrations ve routes

    Bir public HTTP API ve iki private integration kurduk. $default stage URL’yi kökte sunar, auto-deploy route değişikliklerini yayına alır. Her integration’da Overwrite path = $request.path ile backend’in beklediği path’i koruduk. Route olmadan doğru path/method Gateway’den backend’e gitmez.

  7. Agent’ı public Gateway adresine bağlamak

    Bir REST route’u eklemek, Agent’ın HTTP istemcisinin hedefini kendiliğinden değiştirmez. BILLING_API_BASE_URL güncellendiğinde Agent, Billing’e aynı EC2 üzerinde olsa da Gateway üzerinden gitmeye başladı. EC2’de curl ile 200, restart sonrasında active, Chat tool trace’inde query_bill gördük.

  8. Canlı akışları doğrulamak

    Login ve fatura sorgusu çalıştı. Birleşik Chat yanıtı REST kullanım kaydı ile MCP kuralını birleştirdi. Simüle 20 dolar ödemeyle Ekim bakiyesi 80’den 60 dolara düştü. Operatör akışında Kasım faturası, güncel 50 dakikayı hesaplamadan sonra kaydetti.

Kurulum komutlarını tekrar hatırlamak
  • ssh -i ve scp -i EC2’ye seçilen private key dosyasıyla bağlanır. Windows dosya izinleri fazla genişse OpenSSH key’i kullanmaz.
  • apt-get update paket listesini tazeler. Docker deposu ve GPG key, ARM64 Ubuntu için uygun Docker paketinin kaynağını ve imza kontrolünü tanımlar.
  • docker compose -f … up -d --wait postgres ayar dosyalarını birleştirir, PostgreSQL’i arka planda başlatır ve healthcheck sonucunu bekler.
  • .venv/bin/python -m pip check kurulu Python paketlerinin bağımlılık uyumunu kontrol eder. İlgili paketleri import etmek, interpreter’ın bu paketleri gerçekten bulduğunu gösterir.
  • systemctl daemon-reload unit tanımını tekrar okutur. enable --now servisleri şimdi ve sonraki açılışlarda başlatır. Env değişikliğinden sonra restart, servisin yeni değeri okumasını sağlar.
  • curl -fsS HTTP hatası olduğunda başarısız olur ve hatayı gösterir. Agent adresini değiştirmeden önce EC2’den Gateway üzerinden demo faturasını 200 ile almıştık.

Hocanın istediği ve elimizdeki kanıt

Grup 2 belgesi, Agent’ın Billing REST çağrıları dahil tüm proje REST operasyonlarının Gateway’den geçmesini istiyor. MCP için ayrı yol öngörüyor. Belgede Cloud Map veya ayrı Security Group isimleri belirtilmiyor. Bu kaynaklar AWS’de private bağlantıyı kurmak için seçtiğimiz parçalar.

  • Bu oturumda AWS’de
    Login, REST-only fatura özeti, birleşik REST + MCP, simüle ödeme ve operatör işlemlerini ekran ve terminal çıktılarında gördük. Birleşik test, JWT’li fatura detayının Agent üzerinden çalıştığını da gösterdi.
  • Toplanacak teslim kanıtı
    Ayrı bir MCP-only AWS ekran görüntüsü, üç farklı MCP retrieval örneği, Gateway’de korumalı route için başarı ve hata çıktısı, test çalıştırma kanıtı ve kısa demo videosu. Yerel demo ve kodun mevcut olması, bunların AWS ekran kaydı olarak hazır olduğunu tek başına göstermez.
  • README ve repo
    Canlı Gateway URL’si ve route tablosu, deploy komutları, varsayımlar, Swagger/OpenAPI, ER diyagramı, MCP tool şeması ve indeksleme yaklaşımı, maliyet notu ile test talimatı ve kanıtları.
